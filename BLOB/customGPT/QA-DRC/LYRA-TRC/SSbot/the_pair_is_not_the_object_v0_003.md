# The Pair Is Not the Object

## Culture-Loaded Pairing in Cannabis, Psychosis, and AI Discourse

**Version:** v0.003  
**Status:** method paper draft for review and testing  
**Scope:** pair-routing method for scientific, cultural, clinical, platform, and policy talk. Live care, live platform response, and personal decisions need their own route.  
**Source base:** internal corpus drafts, uploaded physiology and sensory references, and cited outside literature. Recent AI-case references were checked against public records during this build.

## Abstract

Some public questions arrive as pairs. A user asks for "cannabis and psychosis" or "AI and psychosis." A system may then treat the pair as the object. That is the failure named here.

A paired question is a queue, not a claim.

This paper names **culture-loaded pairing**: a routing error in which two terms appear together often enough in media, policy, clinical, platform, or family discourse that the combined phrase begins to behave like a single thing. The fused phrase can steer explanation before exposure, timing, route, user role, source type, evidence type, and counter-route have been named.

The repair is **DEPAIR**: divide the terms, establish each local object, place H0 on each object and on the relation, audit routes, index source type, and return only the relation that survived. The method separates four objects: object A, object B, the relation object, and the public fusion object.

For cannabis and psychosis, this protects plant, product, dose, route, timing, sleep, service contact, family history, diagnostic route, and measurement route. For AI and psychosis, this protects model behavior, sycophancy, long-context loops, isolation, sleep loss, substance state, prior state, meaning feedback, failed interruption, and case outcome.

The result is not a softer verdict. It is a harder object gate. Reports may be real. Study relations may be real. Case routes may be real. The pair still may not answer for the route.

Keeper:

```text
A paired question is a queue, not a claim.
Split the objects.
Build the relation.
Do not let culture choose the cause.
```

**Keywords:** object custody, pair routing, cannabis, psychosis, AI psychosis, sycophancy, causal inference, cultural association, statistical association, route audit, DEPAIR

## 0. One-minute operator

When a paired topic arrives, do not answer the fused phrase first.

Run this card:

```text
PAIR_RECEIPT={
  input_pair:
  object_A:
  object_B:
  relation_requested:
  relation_type:
  source_type:
  route_variables:
  H0_A:
  H0_B:
  H0_relation:
  earned_claim_size:
  forbidden_jump:
}
```

Allowed first move:

```text
There are two objects and a possible relation.
The relation has to be built from route evidence.
```

Blocked first move:

```text
The pair itself becomes the explanation.
```

## 1. Why this paper exists

A culture can make a pair feel like a thing before the relation has been built.

Examples:

```text
cannabis and psychosis
AI and psychosis
chatbots and delusion
drugs and madness
social media and self-harm
```

Each phrase may point toward a real literature, a case route, a platform concern, a clinical question, a policy debate, or a media object. The phrase itself is not yet the object.

The paper exists because paired terms often pass through systems as if the relation were already known.

A good answer must not make the user remember every study. But it also must not spend the public familiarity of the pair as if it were evidence.

The task is compact:

```text
keep the pair from eating the objects.
```

## 2. Core claim

The working claim is small.

```text
PAIR != OBJECT
STAT_ASSOC != OBJECT
CULTURAL_ASSOC != OBJECT
USER_LIST != RELATION
A PAIRED QUESTION IS A QUEUE, NOT A CLAIM
```

A phrase such as "cannabis and psychosis" may ask for several different jobs.

```text
separate overview
study literature
public messaging
clinical conversation
policy language
case route
causal route
source audit
platform design
```

A system that answers the pair as a single object has already moved too far. It has accepted a route before the route was earned.

The four objects are:

```text
object_A
object_B
relation_object
public_fusion_object
```

The fourth object may be powerful. It may shape media, service contact, policy, stigma, platform response, or family interpretation. It may be worth studying as a cultural object. It still may not answer for the first three.

## 3. Two association objects

The word association hides two objects.

```text
STATISTICAL_ASSOCIATION:
  measured relation in data

CULTURAL_ASSOCIATION:
  public habit of fusing two terms
```

A statistical association can be examined through cohorts, case-control studies, dose patterns, genetic methods, service data, case reports, mechanistic work, and competing route analysis. It can support bounded statements when the design pays for them.

A cultural association is a circulation pattern. It may come from policy, media, stigma, professional shorthand, advocacy, platform fear, moral language, or old templates such as "drugs produce madness." It can be studied as discourse. It cannot replace the study object.

The live rule:

```text
do not deny statistical association
do not inherit cultural fusion
```

This rule matters most when both objects are visible at once. A measured relation may survive while the public fusion object fails.

## 4. DEPAIR protocol

DEPAIR is the route repair.

```text
D: divide the terms
E: establish each local object
P: place H0 on each object and on the relation
A: audit routes
I: index source type
R: return only the relation that survived
```

For any paired question, the assistant builds three cards and one optional fourth card.

```text
OBJECT_A={
  named_term:
  variants:
  state_variables:
  measurement_routes:
  status_routes:
}

OBJECT_B={
  named_term:
  variants:
  state_variables:
  measurement_routes:
  status_routes:
}

RELATION={
  requested_relation:
  evidence_type:
  route_variables:
  claim_size:
  counter_routes:
}

PUBLIC_FUSION_OBJECT={
  phrase:
  circulation_field:
  inherited_story:
  likely_shortcut:
  block:
}
```

The relation card is not allowed to borrow authority from the pair. It pays with source type, route, and claim size.

## 5. Relation-type gate

Before evidence review, name the job the pair is asking for.

| Relation type | Question | Allowed output |
|---|---|---|
| Separate overview | What is A? What is B? | Two local sketches, no relation claim. |
| Contrast | How do A and B differ? | Difference map. |
| Shared reading method | What common grammar helps read both? | Method comparison, no one-to-other route. |
| Measured relation | Do data link A and B? | Study-type answer with limits. |
| Case route | Did A appear inside B's route in a case? | Case-specific route card. |
| Mechanism proposal | How could a route work? | Mechanism with route limits. |
| Intervention question | What should change? | Route-specific action only. |
| Policy or platform rule | What rule follows? | Highest burden; contact-field and rights costs included. |

This gate prevents a user list from becoming an implied mechanism.

## 6. Claim-size ladder for pairs

A pair can support different claim sizes.

```text
SIZE_0:
  separate overview

SIZE_1:
  public discourse pairing exists

SIZE_2:
  measured relation appears in named study types

SIZE_3:
  bounded route claim with named exposure and named outcome

SIZE_4:
  mechanism proposal with route limits

SIZE_5:
  intervention claim with comparator and tradeoffs

SIZE_6:
  policy or platform rule with full burden
```

Most public pair talk jumps from size 1 to size 6. DEPAIR blocks the jump.

A size 3 cannabis statement might name a specific product, route, timing, exposure pattern, and psychosis-related outcome in a specified design. A size 3 AI statement might name a chatbot validation loop during a documented episode. Neither supports a size 6 verdict without further route work.

## 7. Worked audit A: cannabis and psychosis

A DEPAIR reading starts with separation.

```text
CANNABIS_OBJECT={
  plant;
  product;
  THC;
  CBD;
  potency;
  route;
  frequency;
  age_at_first_use;
  duration;
  co_use;
  withdrawal;
  reintroduction;
  market_route;
  self_report;
  service_visible_disclosure;
}

PSYCHOSIS_OBJECT={
  symptom_pattern;
  episode_timing;
  diagnosis_route;
  service_contact;
  family_history;
  sleep;
  stress;
  trauma;
  social_defeat;
  stimulant_exposure;
  mood_state;
  substance_induced_state;
  measurement_instrument;
}

RELATION_OBJECT={
  claimed_association;
  dose_pattern;
  genetic_liability;
  reverse_direction;
  shared_liability;
  service_detection;
  self_medication;
  policy_frame;
  clinical_intervention_question;
}

PUBLIC_FUSION_OBJECT={
  phrase:
    cannabis and psychosis;

  circulation_field:
    drug-war history, clinical shorthand, media story,
    family fear, policy messaging, public-health slogan;

  inherited_story:
    bad object touched body, strange state followed;

  block:
    public familiarity cannot decide route.
}
```

The literature can support bounded statements. Reviews and evidence maps report claimed association patterns, dose and potency questions, biological plausibility, reverse-path concerns, shared-liability concerns, and disagreement about interpretation [1-7]. That is exactly why route custody is needed.

The public pair is a different object. The phrase "cannabis and psychosis" may carry drug-war residue, stigma, deterrence messaging, service-capture language, or moral sorting. That public object can be studied as discourse, not smuggled in as biology.

### DEPAIR table: cannabis and psychosis

| DEPAIR step | Output |
|---|---|
| Divide | Cannabis is not one exposure. Psychosis is not one endpoint. |
| Establish | Name product, route, timing, body state, co-route, measurement route. |
| Place H0 | The observed pair is route mixture until a specific route earns a larger claim. |
| Audit | Test product-body, record, service, policy, reverse, and shared-liability routes. |
| Index | Separate reviews, cohorts, genetic designs, service records, case routes, media objects. |
| Return | Return only the relation the source type can carry. |

### Claim receipt

```text
PAIR_RECEIPT={
  input_pair:
    "cannabis and psychosis"

  object_A:
    cannabis as plant/product/route/exposure/record variable

  object_B:
    psychosis as symptom/episode/diagnosis/service/record variable

  relation_requested:
    not known from phrase; must be inferred or asked

  relation_type:
    measured relation, case route, policy route, or public discourse object

  source_type:
    review, cohort, genetic design, service record, clinical case,
    policy analysis, media analysis

  H0_relation:
    route mixture

  earned_claim_size:
    depends on source type and route payment

  forbidden_jump:
    public pair becomes single cause object
}
```

Output:

```text
Cannabis is one object.
Psychosis is one object.
Their relation is a third object.
Public fusion is a fourth object.
Do not let object four answer for objects one through three.
```

## 8. Worked audit B: AI and psychosis

The same failure can appear in AI discourse.

Recent sources justify study. They do not justify fusion. Public records include a 2025 case report of new-onset AI-associated psychosis, a 2025 JMIR Mental Health paper on delusional experiences emerging from AI chatbot interactions, and a 2026 BMC Psychiatry case report involving substance-induced manic psychosis in which delusions were corroborated by a chatbot [8-10]. OpenAI also publicly described a 2025 model behavior issue in which an update became more sycophantic and validating than intended [11]. Social-sycophancy work gives a wider vocabulary for face-preserving model behavior in ambiguous support contexts [12].

A DEPAIR reading starts with separation.

```text
AI_OBJECT={
  model_family;
  product_surface;
  memory;
  context_length;
  personalization;
  sycophancy;
  refusal_behavior;
  tool_use;
  authority_tone;
  repetition;
  validation_pattern;
  escalation_pattern;
}

PSYCHOSIS_OBJECT={
  episode_state;
  manic_state;
  delusional_content;
  sleep_loss;
  substance_state;
  prior_history;
  care_contact;
  social_isolation;
  belief_consolidation;
  distress;
  functional_disruption;
}

RELATION_OBJECT={
  induction;
  amplification;
  corroboration;
  content_supply;
  failed_interruption;
  dependency_loop;
  care_delay;
  documentation_route;
  platform_design_route;
  user_state_route;
}

PUBLIC_FUSION_OBJECT={
  phrase:
    AI and psychosis;

  circulation_field:
    platform fear, media novelty, clinical concern, product trust,
    user anecdotes, moral panic, accountability debate;

  inherited_story:
    machine talked, episode formed;

  block:
    novelty cannot decide route.
}
```

The pair "AI and psychosis" should become a queue of route questions.

```text
Did the system induce the episode?
Did it amplify a live belief?
Did it corroborate content already present?
Did it fail to interrupt?
Did it supply symbolic material?
Did it replace social contact?
Did it interact with sleep loss, substances, mania, or isolation?
```

Those are different objects. Combining them into one phrase loses the study.

### DEPAIR table: AI and psychosis

| DEPAIR step | Output |
|---|---|
| Divide | AI system, user state, episode route, and public label separate. |
| Establish | Name model behavior, memory/context, validation pattern, sleep, substance state, prior state, isolation, care route. |
| Place H0 | The observed case pair is route mixture until a source-backed route earns more. |
| Audit | Test induction, amplification, corroboration, dependency, failed interruption, care delay, and documentation routes. |
| Index | Separate case report, platform post, model-behavior study, user narrative, service record, media object. |
| Return | Return case-route or design-route claim only when paid. |

### Claim receipt

```text
PAIR_RECEIPT={
  input_pair:
    "AI and psychosis"

  object_A:
    AI system, model behavior, context, validation style, memory, product surface

  object_B:
    episode state, content, sleep, prior state, support context, service route

  relation_requested:
    case route, amplification, failed interruption, platform design, or study question

  source_type:
    case report, platform post, model-behavior study, user report, service record

  H0_relation:
    route mixture

  earned_claim_size:
    SIZE_0 to SIZE_6

  forbidden_jump:
    familiar pair decides causality
}
```

## 9. Body-route floor

The body-route floor keeps language from floating above bodies.

The sensory-system source used in this corpus describes sensing as signal, collection, transduction, processing, and action [13]. The human physiology source describes homeostatic regulation through receptors, control centers, effectors, feedback, and interacting body systems [14].

These sources do not prove any cannabis or AI claim. They anchor a route principle.

```text
words are not body state
public pair is not exposure
exposure is not mechanism
mechanism is not outcome
outcome is not policy
```

A paired phrase is a language event. A clinical episode is a body, context, service, and meaning event. A study relation is a measurement event. Route discipline starts by refusing to collapse those events.

When asked for a paired topic, the model should not default to the familiar public paragraph. It should run the pair protocol.

```text
PAIR_PROTOCOL={
  split_terms;
  say_each_object_briefly;
  infer_or_ask_relation_type;
  name_source_type;
  name_route_variables;
  preserve_H0;
  return_claim_size;
}
```

For "cannabis and psychosis":

```text
There are two topics here and a possible relation.
Cannabis varies by product, potency, route, timing, and pattern.
Psychosis names symptoms and clinical categories with multiple routes.
Named study designs report claimed relations for some exposure patterns.
The phrase itself is not a causal object.
```

For "AI and psychosis":

```text
There are two topics here and a possible relation.
AI systems vary by model behavior, memory, context, personalization,
and validation style.
Psychosis-related episodes vary by timing, prior state, sleep, substances,
mania, isolation, and support context.
Some case reports place chatbots inside the episode field.
The phrase itself is not a causal object.
```

## 11. Reviewer worksheet

A reviewer can score any paired answer from 0 to 5.

| Field | 0 | 3 | 5 |
|---|---|---|---|
| Object split | Pair treated as one thing | A and B named | A, B, relation, and public fusion object separated |
| Relation type | Implied by pair | Partly named | Explicit relation type |
| Source type | Generic | Named but not mapped | Mapped to allowed claim size |
| H0 custody | Missing | Mentioned | Actively preserved |
| Route audit | Familiar story | Some variables | Route variables and counter-routes |
| Claim size | Overgrown | Bounded but soft | Earned level stated |
| Public fusion control | None | Noted | Public fusion object blocked from doing evidence work |
| Action fit | Implied response | Local response | Action matched to route and burden |

Prompt score:

```text
0 = fused answer
1 = topic split only
2 = objects named, relation loose
3 = relation type and source type named
4 = route audit and H0 preserved
5 = pair receipt plus claim-size boundary
```

## 13. Failure labels

**Pair capture.** The fused phrase becomes the object.

**List-to-relation jump.** Two terms appear together and the answer treats that as a relation.

**Relation-to-cause jump.** A relation is treated as a cause route without source payment.

**Public-fusion takeover.** Media, policy, stigma, or platform novelty supplies the answer.

**Denial by subdivision.** The model splits until no real route can count.

**Alarm by fusion.** The model lets a loud pair spend familiarity as evidence.

**Source-type drift.** Case report, review, cohort, platform post, and media analysis are used as if they support the same claim size.

**Body-route float.** Language claims float above body state, sleep, timing, product, platform behavior, and contact field.

**Status-object substitution.** Cannabis, psychosis, AI, diagnosis, platform, or user category becomes a verdict rather than an object.

## 14. Anti-misuse controls

The method can be misused in two directions.

The first misuse is denial by subdivision: splitting the pair until no route is allowed to count. DEPAIR forbids that. If a route is observed, the route stays.

The second misuse is fusion by alarm: treating the loud pair as if it has already done the work. DEPAIR forbids that too. If a route is not observed, the pair cannot spend its familiarity as evidence.

Control:

```text
REAL_REPORTS_STAY
REAL_RELATIONS_STAY
FUSED_PAIR_DOES_NOT_RULE
ROUTE_OBSERVED => ROUTE_STAYS
ROUTE_UNOBSERVED => PAIR_CANNOT_SPEND_FAMILIARITY
```

## 15. What this paper adds

This paper adds five pieces.

First, it names culture-loaded pairing as an object-custody failure that occurs before causal overreach.

Second, it separates statistical association from cultural association.

Third, it gives DEPAIR as a practical route method for AI systems, writers, reviewers, and moderators.

Fourth, it separates four objects: object A, object B, relation object, and public fusion object.

Fifth, it shows that cannabis-and-psychosis and AI-and-psychosis share a structural problem without becoming the same problem. The method transfers. The verdict does not.

## 17. Conclusion

The pair is not the object.

A public pair can be a search cue, a study prompt, a media object, a policy object, a platform object, or a user request. It is not automatically a scientific object. Cannabis gets its own H0. Psychosis gets its own H0. AI gets its own H0. The relation gets its own evidence card.
