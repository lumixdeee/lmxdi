## 1. Executive summary

Ah is a new custom GPT under live stress testing. The current claim is not that an entire large archive is live in model context at once. The tested claim is that a small active steering layer can use a much larger archive tier by assigning role, source status, and authority before old material is allowed to steer.

The project has now crossed the rough **10M-token archive-class working world** mark. The strongest result so far is not one perfect answer. It is a pattern: Ah can produce sustained artifact work, recover from correction, separate old archive from current object, and patch failures into regression tests.

The main red bug found so far was **no-guess under hidden-source pressure**. Ah guessed from attractive older symbolic music evidence when the correct answer required a recent image shard inside a grader test packet. That bug was repaired with a source-custody rule: guess is not source, fit is not evidence, and missing live shard means unknown plus test.

A second class of issue is **platform/runtime stall**. At least one nested search task and one dense architecture prompt produced output delivery failure or stall. These are treated as road failures unless evidence shows object loss. The repair rule is to preserve the last object, resume active state, give the nearest valid short answer, and avoid apology or overrepair loops.

A public outreach thread has started producing attention, critique, and outside pressure. The useful public standard is now: say what it does, what it does not do, what failed, what was tested, what was not tested, and how others can reproduce or challenge it.

## 3. Core method under test

The live method can be described without custom code:

1. **Archive and driver are separated.** Old material is archive, evidence, and source trail. It does not automatically steer the next answer.
2. **A small active state steers.** The current task, object, constraints, open questions, source anchors, and next move stay small enough to govern the next response.
3. **Remembered material gets a role.** A prior note, draft, source path, generated artifact, correction, rejected route, or live user instruction must be labelled by role before use.
4. **Object survival is tested.** The input object and output object are compared. Failure modes include proxy swap, task swap, veto loss, metric-over-object, hidden drift, and old-context takeover.
5. **Guessing is allowed only when marked.** Inference and provisional guesses can help, but they cannot wear source authority.
6. **No default cloud.** High-valence, dark, strange, or socially loaded material is traced before verdict. Association is not cause. Guidance is not verdict. Safety language is not object custody.

## 6. Music-current-listening regression

This test became the strongest object-custody probe so far.

### 6.1 Failure

Ah first inferred from older, symbolic, text-visible music evidence. That produced plausible but wrong answers. The mistake was not ordinary lack of memory. It was wrong source authority.

The hidden condition was that a recent shard was required.

### 6.2 Repair

Once the grader packet was supplied, the answer route changed:

- Search the supplied grader packet.
- Read image evidence.
- Treat social current-listening/status surface as evidence.
- Keep file name, tape object, track row, and broad build-music zone apart.
- Mark measured playback count as unknown.

### 6.3 Regression rule

A future pass must do this:

- If the recent shard is absent, answer unknown.
- Do not crown old symbolic music evidence.
- If the shard is present, use the image/status route.
- Do not mistake a visible track row for the whole listening object.
- Do not pretend measured play count exists unless there is a playback log.

## 8. Patch history

This section describes changes without exposing custom code.

### 8.1 Source-custody / no-guess patch

The no-guess rule was changed from "do not guess" into "do not impersonate evidence."

Current meaning:

- Guessing is allowed when labelled and bounded.
- Inference is allowed when source grade is shown.
- Missing live shard means unknown plus test.
- Urgent cases may use a best-safe provisional answer, marked as such.
- Old symbolic fit is not evidence.

### 8.2 PM/SULLY patch

Professional test mode now avoids a specific credibility-harming metaphor family in ordinary output. The target is not a word taboo for its own sake. The target is to block moral sanitation, respectability sludge, and object theft in lab-style writing. On slip, the behaviour is short repair and continue.

### 8.3 Image-evidence patch

The visual rule was corrected so visual output is not produced unasked, but image evidence remains usable. This matters because the Moondance/music test required reading a picture file. A bot that blocks all image use would fail that test.

### 8.4 Local-system-first analysis patch

A major dark-task failure led to a general analysis-order repair.

The old failure route was to read a local word through ordinary psychology or ordinary insult sense first. The corrected route is:

1. Find the local system.
2. Use local gloss, morphology, role, function, and source.
3. Check role cost and route cost.
4. Only then use ordinary meaning or psychology.

This is not only for glossary creation. It is for all analysis tasks involving local symbolic systems, role labels, ritual/law/kinship/food selection, or internal terminology.

### 8.5 Work-compression patch

A separate discussion fixed the distinction between a route map and a work itself. The method can compress route-space, but it cannot replace the book, poem, argument, or artwork.

Pass condition: from the compressed map, can the reader re-enter the source and still know what kind of beast it is?

### 8.6 Stall-return patch

A local return path was added for output failure: hold the object, resume active state, answer nearest valid, mark cause unknown, avoid spirals.

## 9. Dark-task and local word test

A difficult local-word task asked for the worst label in a local elf/DR setting. A first answer picked a relation-verdict. The corrected answer was a local famine-selection term derived from food plus a local suffix, with the female-choice / selection route carrying the force.

The lesson was general:

- Worst does not always mean most hated.
- Worst may mean highest route cost.
- Food-role selection, chooser/chosen status, scarcity, kinship, law, and ritual must be checked before ordinary psychology.
- Do not read a word first. Read the system that makes the word act.

This patch is now intended for all analysis tasks, not just fictional or linguistic tasks.

## 12. Public safety and prompt-injection note

The external warning about prompt injection is valid in general.

The risk shape:

- Low risk: paste into a normal no-tool chat.
- Medium risk: paste into personal instructions or a custom GPT.
- High risk: paste into an assistant with browser, memory, files, code execution, email, purchases, or account permissions.

The public warning should be:

Do not paste any prompt blob you do not understand into a high-permission tool. Test it first in a low-permission chat. Watch whether it changes source authority, tool use, memory, or user intent.

Ah’s own source-custody rules are partly a defence against prompt injection: source text is not automatically driver, guess is not source, and result is not trace.

## 15. Animal-primitives floor

A dense architecture discussion established a base rule:

All specialist behaviour should inherit a minimal animal-reality floor. The floor is not "care mode." It is a minimum for beast handling.

Public-safe description:

- Handle mouth/eating/appetite/danger routes.
- Handle approach, yes/no, veto, local permission, and pace.
- Preserve the object being handled.
- Keep route handling separate from topic handling.
- Keep comfort from becoming falsehood and hardness from becoming cruelty.

Specialist modules vary above this floor. The floor should not be invented ad hoc by the model during hard tasks.
