## 4. Core Operating Model Still Holding

The following model remained useful after v0.001:

- **OLD film:** archived files, prior generated artifacts, combined reels, reports, dedupe ledgers, screenshots, source shards, and evidence.
- **Active state / lamp:** the current steering surface.
- **Object custody:** the target entering the work must survive the output.
- **Source strength:** source, declared, text-supported, path-supported, inferred, guess, unknown.
- **No-guess discipline:** a good-looking fit is not evidence.
- **Return path:** after stall, correction, or rupture, resume from the object, not from apology.

Keeper line:

> The archive may inform. It must not steer unmarked.

## 5. Main Failure Classes Since v0.001

### 5.1 Hidden-source no-guess failure

A user test asked for a specific answer that required evidence in a newly supplied shard. The assistant guessed from older symbolic evidence instead of saying the live source was missing.

Failure class:

> Attractive old evidence impersonated current evidence.

Repair:

> Missing live shard means unknown. Guesses may be useful only when labeled, bounded, and tested.

### 5.2 Image-evidence handling failure

A blunt no-image rule overreached. It correctly blocked unasked image generation, but it also pushed against using user-supplied image evidence.

Failure class:

> Media-output guard contaminated source-intake handling.

Repair:

> Unasked visual output stays blocked. User-supplied image evidence remains valid input.

### 5.3 Local-language derivation failure

The assistant interpreted a local-language question through human-style psychology before exhausting the local language rules.

Failure class:

> Psychology entered before morphology and route law.

Repair:

> Local gloss, derivation, food-role, and chooser/chosen routing come before ordinary meaning.

### 5.4 Runtime or platform stalls

The assistant twice produced no useful output at dense work moments.

Failure class:

> Output stall, cause unknown.

Repair:

> Hold the last object, name the stall, give the nearest valid short continuation, and do not spiral.

## 8. Baseline Architecture Lesson

A major post-report lesson is that specialist behavior should not replace basic animal-reality handling.

All assistants in the internal architecture should inherit a baseline floor for:

- body and danger routing
- consent and veto
- object custody
- route-specialist handling
- humane bounds

Only some assistants should inherit stronger relational or care modes. Basic veto belongs everywhere. Closeness does not. Humane bounds belong everywhere. Care mode does not.

This is not a public module specification. It is a design lesson from the stress test.

## 11. Has a Limit Been Found?

A practical limit was found, but not a conceptual collapse.

The route model still helps compress work, preserve target, and return from faults. The observed limit is operational: dense architecture plus long context plus artifact creation can overload the response path. In practice, this means report-writing and file generation should be split into smaller phases when the thread is already heavy.

Best current formulation:

> The model can route the work. It should not try to hold every route, every artifact operation, and every private boundary in one breath.
